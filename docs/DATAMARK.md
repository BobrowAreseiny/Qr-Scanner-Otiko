# Электронный знак (Datamark)

## Система

ГИС «Электронный знак» — государственная система маркировки Республики Беларусь. Оператор — РУП «Издательство «Белбланкавыд».

## Адреса

- API: `https://api.datamark.by/`
- Личный кабинет: `https://i.datamark.by/`

`https://i.datamark.by/auth` — страница входа в личный кабинет, а не API. POST-запрос к ней возвращает HTTP 405.

Авторизация API:

```http
POST https://api.datamark.by/auth
Content-Type: multipart/form-data
username=<логин>
password=<пароль>
```

Поиск товара:

```http
POST https://api.datamark.by/items/findItems
Token: <токен>
Content-Type: application/json

{"search":"<GTIN>"}
```

## Настройки приложения

- Сервер: `https://api.datamark.by/`
- Логин и пароль сохраняются в `SecureStorage`.
- Данные можно изменить в любой момент.
- После смены пароля кэш токена сбрасывается, выполняется повторная авторизация.
- Без авторизации марки не добавляются.
- Поддерживается импорт из `credentials.txt`: каталог приложения `files` или внешний `Android/data/<package>/files`.
- Форматы файла: две строки `логин` и `пароль`, строки `username=...` / `password=...` или JSON с полями `username` и `password`.
- Пробелы в начале и конце логина и пароля обрезаются.

## Проверка доступа

- API `/auth` с рабочим паролем вернул HTTP 200.
- Пароль должен содержать не менее 8 символов, заглавную латинскую букву, цифру и спецсимвол. Без спецсимвола API возвращает 400; при неверном пароле — 401.
- Личный кабинет `i.datamark.by` и API `api.datamark.by` могут требовать разные учётные данные.
- Поиск GTIN `04810498044822` вернул товар: `articul=1549`, `gtin_check=true`, `group=shoes`, `is_my=true`, размер `37`.

Пароль в коде приложения не хранится и в Git не попадает.

## Безопасность учётных данных

- Логин и пароль сохраняются только в `SecureStorage` (Android Keystore).
- Пароль очищается из формы при уходе с экрана настроек.
- `credentials.txt` хранит пароль в открытом виде. После импорта файл нужно удалить; в настройках есть отдельная кнопка удаления.
- Импорт из `credentials.txt` выполняется только при отсутствии сохранённых данных или по кнопке.
- Токен хранится только в памяти и не пишется в файлы и логи.
- Используется HTTPS с проверкой сертификата; отключение проверки не предусмотрено.

## API по спецификации 4.29

Спецификация: WEB-сервис межсистемного взаимодействия, редакция 4.29, 2026.

### Адреса

- Продуктивный контур: `https://api.datamark.by`
- Тестовый контур: `https://sandbox-api.datamark.by`

REST, HTTPS, TLS 1.2+. Тело запроса и ответа — JSON UTF-8. Методы: GET, POST, PUT.

### Авторизация

```http
POST /auth
Content-Type: multipart/form-data | application/x-www-form-urlencoded | application/json
username=<e-mail>
password=<пароль>
```

Ответ содержит `token`, `token_refresh`, `user`. Срок действия токена по умолчанию 20 минут. Токен передаётся в заголовке:

```http
Token: <token>
```

При истечении токена выполняется повторная авторизация.

### Поиск товара по GTIN

```http
POST /items/findItems
Token: <token>
Content-Type: application/json

{"search":"04810498044822"}
```

Ответ:

```json
{
  "items": [
    {
      "name": "ПОЛУБОТИНКИ ЖЕНСКИЕ",
      "articul": "25C1",
      "gtin": "04810498044822",
      "gtin_check": true,
      "group": "clothes",
      "is_my": true,
      "params": [
        {"name": "Размер в штихмассовой системе", "display_value": "37"}
      ]
    }
  ]
}
```

Если товар не найден, API возвращает ошибку `2010` — «GTIN товара не найден».

### Проверка кодов маркировки

```http
POST /v2/labels
Token: <token>
Content-Type: application/json

{"labels":["0104810498044822212UJogcqL51WQE\u001d91TEST\u001d92..."]}
```

Не более 1000 кодов за запрос. Ответ по каждому коду:

- `found` — код есть в системе;
- `status` — текущий статус кода;
- `is_my` — принадлежит текущему участнику;
- `type` — тип кода.

### Отгрузки и приёмка

В API есть методы:

- `/ships` — отгрузка кодов;
- `/ships/receipt` — оприходование;
- `/ships/list` — список отгрузок;
- `/reports` — отчёты о маркировке и агрегации;
- `/orders` — заказы кодов.

Их можно использовать на следующем этапе для обмена с 1С и складского учёта.

### Ошибки

- `400` — ошибка входных данных;
- `401` — неверный токен или учётные данные (`1202`, `1203`, `13001`, `13002`);
- `403` — нет прав;
- `404` — данные не найдены;
- `2001` — товар не найден;
- `2010` — GTIN товара не найден.

## Проверка GTIN в приложении

В ветке `feature/gtin-check` реализовано:

- локальная проверка 8/12/13/14 цифр и контрольной суммы GTIN;
- экран «Проверка GTIN» в разделе «Агрегация»;
- ввод GTIN вручную или сканирование кода маркировки;
- извлечение GTIN из GS1 DataMatrix;
- запрос `/items/findItems`;
- отображение названия, артикула, размера, признака `gtin_check`, группы и `is_my`;
- сообщение о необходимости авторизации и переход в настройки;
- проверка GTIN при добавлении марки в короб.

Реальный API проверен: GTIN `04810498044822` найден, артикул `1549`, размер `37`, `gtin_check=true`, группа `shoes`, `is_my=true`.

## Рекомендация

1. Для быстрой проверки кодов на ТСД — установить «Электронный знак» из Google Play.
2. Для работы с партиями и выгрузкой — «Электронный знак. Бизнес» и учётная запись участника.
3. В нашем приложении использовать API `https://api.datamark.by/`; `https://i.datamark.by/` как адрес API не указывать.
4. Для API нужен пароль, соответствующий политике: не менее 8 символов, заглавная латинская буква, цифра и спецсимвол.
