# Обмен с 1С по API

## Решение

Основной способ передачи заказов в 1С — HTTP API.

Файловый экспорт `.txt` сохраняется как резервный и ручной способ до ввода API в промышленную эксплуатацию.

## Компоненты ТСД

| Компонент | Использование |
|---|---|
| `ru.atol.barcodeservice` | Приём сканера через broadcast. |
| `net.soti.mobicontrol.enterprise.atol` | Централизованная установка и обновление APK на парке ТСД. |
| Google Drive, Files, Gmail | Передача резервных копий и файлов, вспомогательный канал. |
| `ru.atol.os.rdp`, браузер | Доступ к 1С и Datamark для диагностики, в приложении не используются. |
| `ru.atol.pdt` (ATOL Mark.Scan) | Ориентир по обмену с 1С; в качестве зависимости не используется. |
| `ru.crptech.b2bmark` (ЧЗ.Бизнес) | Не используется: система РФ, маркировка Datamark имеет другую систему. |

## Архитектура

В приложении предусматривается единый интерфейс экспорта заказа:

- `FileOrderExportService` — существующий `.txt`;
- `OneCApiOrderExportService` — HTTP-обмен с 1С.

Общие требования:

- адрес API и токен задаются в настройках;
- токен хранится в `SecureStorage`;
- пароли и токены не записываются в логи;
- таймаут запроса и повтор при сетевой ошибке;
- идемпотентность по `externalId`;
- статус отправки сохраняется в заказе.

## Контракт API

Предлагаемый контракт, который должна реализовать сторона 1С.

### Отправка заказа

```http
POST {BaseUrl}/api/qrscanner/orders
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "externalId": "6f1c2a7e-9b4d-4f0e-a1c2-3d4e5f607182",
  "name": "Заказ 15.11.2026 10-30",
  "createdAt": "2026-11-15T10:30:00Z",
  "warehouse": "Основной склад",
  "lines": [
    {
      "barcode": "0104810498044822212UJogcqL51WQE91000592...",
      "gtin": "04810498044822",
      "vendorCode": "25C1",
      "size": "37",
      "sourceCorobId": 1
    }
  ]
}
```

### Ответ

```json
{
  "status": "ok",
  "number": "ЗК-000123"
}
```

Коды ответа:

- `200` — заказ принят;
- `409` — заказ с таким `externalId` уже существует, считается успехом;
- `400` — ошибка данных, повтор не выполняется;
- `401`/`403` — ошибка авторизации;
- `5xx` или таймаут — заказ остаётся в очереди на повтор.

### Проверка связи

```http
GET {BaseUrl}/api/qrscanner/health
Authorization: Bearer {token}
```

## Очередь отправки

- заказ сохраняется локально до успешной отправки;
- при ошибке сети статус `Ожидает отправки`;
- повтор — по кнопке и автоматически при следующем запуске;
- после успеха статус `Отправлен`, сохраняются номер 1С и время.

## Открытые вопросы для 1С

- фактический адрес API и тестовый контур;
- способ авторизации: Bearer, Basic или отдельный ключ;
- формат: JSON или XML;
- обязательные поля заказа и строк;
- нужен ли отдельный номер заказа от 1С;
- правила повторной отправки и идемпотентности.

До получения этих данных используется предложенный контракт.
